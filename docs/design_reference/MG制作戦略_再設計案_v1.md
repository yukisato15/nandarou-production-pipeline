# 『なんだろう』解体 MG制作戦略 再設計案 v1

前提:design_v2.py・コンテ表(テロップ規定含む)・ブランド定義v1.1・設計書v4を精読。スクリーンショットは未入手だが、JSXが画を完全に決定しているためコードからレビューした。

## 0. 診断:何が「しょぼい」の正体か

ChatGPTの診断(レイアウト規律の欠如)は**半分だけ正しい**。整列・階層・マージンを完璧にしても、得られるのは「壊れていないスライド」であって「見たくなる映像」ではない。しょぼさの原因は4つ。

1. **光と質感が存在しない。** 画面に写真・粒子・紙のスキャン・光源・被写界深度が一切ない。`darkEditorialGround` は不透明度4〜5%の1pxラインで「編集的な質感」を偽装しているが、フラット塗り+細線は距離ゼロで安っぽさが露呈する。ブランド定義5章の「手ざわり——テープヒス、紙、粒子」がゼロ実装。
2. **図形文法がコンサル資料。** C13の「リング3つ+シェブロン矢印」、C01の「角丸カード+アクセントバー」は、色を変えてもSaaS資料の文法そのもの。低彩度にしただけの説明スライドになっている。
3. **自己言及的な飾り。** `CUT_ID / NND-01`「THE HOOK」「THE EXCHANGE」「01 / THE OBJECT」「///」——これらは視聴者に何の情報も与えない管理ラベルで、「編集的に見せるための装飾」がむしろテンプレ感を生んでいる。ChatGPTの「意味のない管理番号や英字ラベル禁止」はこの点を正確に突いている。
4. **番組自身の規定との乖離。** コンテ表テロップ規定は貂明朝/しっぽり明朝の明朝系がアイデンティティなのに、design_v2はSourceHanSans-Bold(ゴシック)が主役。設計書v4の「明朝系タイポ/分解図・設計図・解剖図モチーフ」と実装が別人格になっている。

結論:**足りないのは規律ではなく材料。** コードは光・質感・写真を発明できない。だからCodexの仮説(素材前提・マスター先行)が基本的に正しい。

## 1. ChatGPT案の採否

| 項目 | 採否 | 理由 |
|---|---|---|
| デザインと実装の分離 | **採用** | 核心。異論なし |
| JSONは座標でなく意味と構造 | **採用** | 現行JSONの方向とも整合 |
| スクリプトの自由装飾禁止 | **採用** | ただし「禁止」だけでは品質は上がらない(材料が要る) |
| セーフマージン・4階層・32px下限・1画面1メッセージ | **採用** | デザイントークンとしてJSON化する |
| 静止画レンダー→検査のQAループ | **採用** | 今の資産で最も価値ある提案 |
| テンプレ分類(title/comparison/bar_chart/quote…) | **棄却** | 情報型で分類すると必然的に「汎用スライド集」になる。分類軸は**画の型(シーンルック)**であるべき。comparison / before_after / cause_effect / timeline は全部「分解図ボード」の1バリアントにすぎない |
| comparison 1種から着手 | **棄却** | comparisonは番組の署名ではない。最初に作るべきは**質感基盤+分解図ボード**(番組の顔) |
| テンプレ10種を最初に定義 | **棄却** | 多すぎる。第1回に必要な画の型は実質7つ |

要するにChatGPT案は「事故を防ぐ設計」としては優秀、「魅力を作る設計」としては空白。両方やる。

## 2. アーキテクチャ:境界の一行定義

> **人間(+AI画像)が「光・質感・構図」を作る。コードは「複製・差し替え・整列・検証」をする。**
> 発明は人間、量産は機械。

- 人間が作るもの:AEマスタープロジェクト(スタイルフレーム確定済みのテンプレコンポ)、ヒーロー素材(偽サムネ・偽広告・AI静止画・紙スキャン)
- コードがやるもの:マスターコンポの複製、テキスト差し替え(sourceRectAtTime実測での折返し/縮小)、素材のインポートとプレースホルダへの配置、尺の合わせ込み、SRT由来のマーカー打ち、チャートのデータ描画、QA静止画のレンダー、AMEキュー投入
- コードが**やらないもの**:色・フォント・余白・装飾の判断、図形からの画づくり

JSX-firstでゼロから描いてよい領域は3つだけ:**①データMG(棒/線グラフ・カウンター・統計カード)②字幕/テロップ ③検証・整列ロジック**。ただし①も「素のコンポに描く」のをやめ、質感・粒子・カメラ揺れを持つマスターコンポの**中の描画エリアに**描く。チャート線はコードが引き、画になるのはマスターの仕事。

## 3. マスター一覧(基盤1+シーン7)

### L0. LOOK_GLOBAL(基盤・最優先投資)
全カットの上に載る仕上げスタック。紙/墨の背景プレート(実スキャンまたはEnvatoテクスチャ)、フィルムグレイン、ビネット、ごく薄い色収差、常時微動のカメラリグ(2〜4pxドリフト)、質感切替トランジション(設計書v4「トランジション=質感切り替え点」)。**これ1つで全テンプレの画質が一段上がる。** 手作業100%、一度作れば全15回で償却。

### M1. FEED / 画面の中(C01, C02, C11, C26)
- 入力:偽サムネ・偽広告のPNG(人間+AI画像で制作)、UIモックの画面収録
- 出力:スマホ/ブラウザの「画面」を撮っている画。暗い部屋、画面のグロー、指/カーソル
- 手作業:UIモックのデザイン、ライティング
- 自動:サムネPNGの差し替え、着弾タイミング(SE同期)、通知バッジの数値
- 補足:UIモックは**HTML/CSSで組んで画面収録**が最速で本物に見える。HTML生成はコードの得意領域なので、ここは「HTML→収録→AE」でコード資産を活かせる

### M2. KAITAI_BOARD / 分解図ボード(番組の署名。C13, C25, C24, 以後の構造回ほぼ全部)
- 入力:中央に置く画像1〜3点(AI静止画・切り抜き写真・スクリーンショット)、ラベル文言、接続関係
- 出力:紙(実テクスチャ)の上に対象をピン留めし、手引きの線(トリムパス+ラフエッジ)と明朝ラベルで解剖する画。カメラが横長ボード(3200×1080等)をドリーする
- 手作業:ボードの構図、画像の切り抜き・配置
- 自動:ラベル文言差し替え、線の描画タイミング、カメラ移動の尺合わせ
- comparison / before_after / cause_effect / timeline は全部このボードのレイアウトバリアント

### M3. DATA_KIT / データMG(C12, C15, C16, C48)
- 入力:JSONのデータ配列(値・ラベル・単位・出典)
- 出力:紙背景+明朝ラベル+Oswald数字のチャート。バー先端は塗りでなくインクの質感、出典表記を規定位置に常設
- 手作業:初回のルック確定のみ
- 自動:ほぼ100%(現行コード資産の主な生き残り先)

### M4. ARCHIVE / 歴史コラージュ(C22〜C28, 以後の歴史パート)
- 入力:AI静止画(歴史・抽象限定=設計書v4準拠)、紙片・テープ・写真コーナーの素材
- 出力:セピアの紙上コラージュ、レイヤー分解した静止画の2.5Dパララックス
- 手作業:静止画の生成・レイヤー分割・コラージュ構図
- 自動:配置の複製、尺、パララックス量のプリセット適用

### M5. OVERLAY / 実写の上の注釈(C46ほか)
- 入力:Envato実写、値札/タグのテンプレ(デザイン確定済み)
- 出力:実写の上に値札が増殖していく画
- 手作業:トラッキング/ピン打ち
- 自動:タグ文言・出現数・タイミング

### M6. STATEMENT / ★幹テロップ(全回)
- 入力:★文、強調1語
- 出力:S2規定(貂明朝Bold 78px、金茶1語)を墨背景+粒子の上で1文字2Fずらし表示
- 自動:ほぼ100%(テロップ規定がそのまま仕様)

### M7. IDENT / ロゴ・次回予告・エンドカード(C52/C54/C55)
- 一度だけ手作業で完成させる。自動化は次回予告の文言差し替えのみ

## 4. C01 / C13 / C25 の作り直し案

### C01(煽りサムネ・フック)
今の実装の根本問題:「サムネ風の角丸カード」を図形で描いている。**この回のサムネは伏線であり、本物のYouTube煽りサムネに見えなければ企画が成立しない。**
- 素材:偽サムネ3枚をPhotoshop/Canvaで**本気で悪趣味に**作る(AI生成の人物なし写真+黄色縁取り極太ゴシック+赤矢印+「終」の一文字等)。実在メディア非模倣はフッターでなく概要欄で処理し、画面からは注記も管理ラベルも消す
- 構図:真っ黒な画面(ルームトーン)。通知音と同時にサムネが**画面奥から手前へ**着弾スタック。わずかな3D回転、着弾時に画面全体が一瞬明るくなる(スクリーングロー)、深度ブラーで前後関係
- モーション:スケール105→100の「ドン」は維持しつつ、着弾ごとにカメラが2〜3px沈む。3枚目以降は加速度的に増えて画面を埋める(コンテの「1枚ごとに画面が埋まっていく」に忠実)
- 見た目の目標:「スライドの上のカード」ではなく「**通知に画面を占拠される体験**」

### C13(視線→再生→広告費)
リング3つ+矢印を全廃。★「売られているのは、あなたの『注意』です」に向かう**1枚の分解図**にする。
- 素材:横長KAITAI_BOARD(3200×1080)。左=目のクローズアップ(AI静止画をレイヤー分割、瞳に画面の反射)/中=回転する再生数カウンター(これはコード描画でよい。UIフォントで本物のUI風に)/右=¥の帳簿・金茶のインク
- モーション:金茶の手引き線が左から右へ**1本だけ**伸び、カメラが線を追ってドリー。各ステージ通過時にラベル(明朝)がスタンプされる。終点で線が「¥」に変わり、カメラが引くとボード全体=★テロップ(M6)へ
- 3つの円を並べて同時に見せるのではなく、**時間で1本の変換を追う**。8分番組の13秒カットとしてはこの方が呼吸が合う

### C25(商品→なれる自分)
- 素材:紙ボード。左=商品の切り抜き写真(直前C24が石鹸広告の話なので石鹸箱が最適。AI静止画可)/右=鏡・シルエット的な「なれる自分」のAI静止画(顔なし=法務規範とも整合)
- モーション:左の商品にラベル「商品」(明朝)→**朱の手描きストローク**(ラフエッジ+トリムパス。今の直線12pxではなく筆致)で打ち消し→金茶の手描き矢印が右へ→右の画像がピンで留まる音とともに出現→★文はM6へ受け渡し
- 「01 / THE OBJECT」等の英字キッカーは全廃。画面に置く文字は日本語ラベル2語と★文だけ

## 5. 素材ソースの使い分け

| ソース | 使う場面 | 使わない場面 |

| 手作業デザイン(Photoshop/Canva/Figma) | 偽サムネ・偽広告・値札・ロゴ等の**ヒーロー素材** | 大量生産が要るもの |

| 自前実写 | 手・机・紙・付箋のインサート(語り手=映像屋の身体性。スマホ+デスクライトで足りる) | — |

## 6. パイプライン最終形

```
コンテxlsx(+素材ID列を追加)
   ├→ SRT字幕 + テロップJSON(完成済み・変更なし)
   └→ MG JSON(意味と構造のみ:template, content, assets[], emphasis, data[])
         │            assets/ フォルダ(命名規約:C13_eye.png 等)
         ▼
   JSXジェネレータ
     1. マスターAEP内のテンプレコンポを複製
     2. テキスト差し替え(実測折返し・縮小、階層トークン準拠)
     3. 素材インポート→プレースホルダ差し替え
     4. データMG描画(M3のみ)
     5. SRTからカットマーカー打ち
     6. レイアウト検査(セーフ域・字幕域侵犯・最小サイズ)
     7. 各カット3点(0%/50%/95%)の静止画をレンダー
         ▼
   静止画QA(人間+AIレビュー)→ NG項目はJSON修正で再生成
         ▼
   人間の仕上げパス(AE):カメラ微調整、質感切替トランジション、音との呼吸
         ▼
   Premiere:ナレ・劇伴・SE・字幕統合
```

QAループ(ChatGPT案G/H)は採用するが、「自動修正」までは狙わない。**静止画を人が見て、JSONを直して再生成**、で十分回る。

## 7. 第1回の切り分けと投資順序

**自動化する(37カット中20前後)**:字幕・テロップ全量/M3データ系(C12, C15, C16, C48ほか)/M6★テロップ/M7の文言差し替え/M1・M2のテキスト・素材差し替え

**手作業に残す**:LOOK_GLOBAL構築/偽サムネ・偽広告・AI静止画などヒーロー素材(10〜15点)/M4コラージュの構図/C46のトラッキング/全トランジション/サウンドと呼吸合わせ

第1回は**5割手作業で正しい**。第1回の手作業は捨てコストではなく、全15回で使うマスターの製造。2回目以降、手作業はヒーロー素材制作と仕上げパスだけに縮む。

**投資順序**(効果の大きい順):
1. LOOK_GLOBAL(質感基盤)——全画面が一段上がる
2. 偽サムネ3枚(C01のヒーロー素材)——第1回の企画根幹
3. M2分解図ボード+C13を1本通す——番組の署名の確定。これがスタイルフレーム承認の場
4. M3データキットをM2のルックに載せ替え——既存コード資産の再生
5. M6/M7——安いのに毎回出る

**捨てる/残す**:
- 捨てる:darkEditorialGround / paperEditorialGround(偽質感)、makeCoverの図形カード、C13のリング+シェブロン、英字キッカー・CUT_ID・「///」等の管理装飾、「37カット全自動配置」という目標そのもの
- 残す:xlsx→SRT/テロップ(完成)、JSONパイプラインの骨格、フォントフォールバック、部分生成・検証・undoGroup・署名コメントの運用、boxTextの実測縮小ロジック、チャート描画コード(M3へ移植)、buildC01の物理感あるドロップモーション(素材が本物になれば活きる)
