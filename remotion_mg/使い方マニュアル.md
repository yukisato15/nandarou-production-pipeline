## 1. これは何？

**JSONという設定ファイルに文字と数字を書くだけで、番組デザインの動画(グラフ・引用・タイトルなど)ができる仕組み**です。

- デザイン(色・フォント・紙の質感・動き)は全部作り込み済み。あなたが触るのは**文字と数字だけ**
- 何度書き出しても同じ画質・同じデザインで出てくる
- Premiereに読み込んで、実写やナレーションと組み合わせて完成させる

```
あなた: JSONに文字と数字を書く
  ↓
この仕組み: 番組ルックの動画にして出す
  ↓
あなた: Premiereで編集に使う
```

## 5. 文字や数字を変える

編集するファイルは `data/` フォルダのJSONです:

| ファイル | 中身 |
|---|---|
| `data/ep01_scenes.json` | 第1回のシーン(9本) |
| `data/ep02_demo.json` | 第2回のシーン(5本) |

VSCodeで開いて、日本語の部分・数字の部分だけ書き換えます。

### よく変える場所

```json
"title": "ぜんぶ、売り物になっていく"   ← タイトルの文言
"value": 195                            ← 棒グラフの数値
"values": [10, 20, 34, 52, 72, 88, 100] ← 折れ線のカーブの形(数列そのもの)
"color": "red"                          ← 線の色: ink(墨) / red(朱) / gold(金茶)
"accentIndex": 3                        ← 棒グラフで朱色にする行(0から数える)
"durationInFrames": 216                 ← シーンの長さ(24コマ≒1秒)
```

### 守ること

- **カンマとダブルクォートを消さない**(JSONの文法エラーになる)
- 色は ink / red / gold の3つだけ(番組ルール)
- 数値がウソにならないよう、演出値なら `"conceptual": true` を付ける(「※概念図」が自動表示される)
- 研究データには `"source": "Vosoughi, Roy & Aral 2018"` のように出典を書く

## 6. 動画に書き出す

```bash
npm run render:scenes                                          # ep02デモを書き出し
npx remotion render JsonScenes out/ep01.mp4 --props=./data/ep01_scenes.json   # 第1回
```

`out/` フォルダにMP4ができます。60秒の動画で3〜5分くらいかかります。

### テロップだけを背景透過で書き出す

Premiereで本編映像の上に重ねる場合は、テロップ専用の透明MOVを書き出します。

```bash
npm run render:telops:sample  # まず短尺サンプルでPremiere確認
npm run render:telops         # 第1回テロップ全尺を書き出し
```

`render:telops` は `data/ep01_telops.json` を読み、透明テロップ動画
`out/ep01_telops_overlay.mov` を作ります。形式はPremiere向けの ProRes 4444 です。
全尺はファイルサイズが大きくなるので、最初は必ず `render:telops:sample` で読み込み確認してください。

## 7. 画の型カタログ(現在6種+一点物1つ)

JSONの `"type"` に書ける名前と用途:

### `title_card` — タイトルカード(墨背景)
回タイトル・章見出し・次回予告に。長いタイトルは自動で縮んで1行に収まる。
```json
{"type": "title_card", "props": {
  "title": "ぜんぶ、売り物になっていく",
  "subtitle": "サブタイトル(省略可)",
  "episode": "『なんだろう』解体 #01"
}}
```

### `statement` — ★宣言(黒背景)
結論の断言に。1文字ずつ現れる。`emphasis`に入れた言葉だけ金茶で大きくなる。
```json
{"type": "statement", "props": {
  "text": "怒りっぽさは、性格ではなく学習です。",
  "emphasis": "学習"
}}
```

### `quote` — 引用(紙片)
歴史上の発言・逸話に。帰属と真偽の注記を必ず付ける。写真も入れられる(下記9章)。
```json
{"type": "quote", "props": {
  "text": "君は絵を用意しろ、戦争は私が用意する。",
  "attribution": "W・R・ハーストに帰される言葉",
  "note": "実話かどうかは定かではない(逸話として伝わる)"
}}
```

### `stat_card` — 研究要点カード
大きな数字・固有名を1〜4個ドンと見せる(MIT / 2018 / 126,000 のような)。
```json
{"type": "stat_card", "props": {
  "title": "ウソはどう広がるか——検証した研究",
  "items": [
    {"value": "MIT", "label": "マサチューセッツ工科大学"},
    {"value": "126,000", "label": "検証されたニュースの件数"}
  ],
  "source": "Vosoughi, Roy & Aral 2018"
}}
```

### `bar_chart` — 横棒グラフ(最大6本)
比較・ランキングに。1本だけ朱で強調できる。数字はカウントアップする。
```json
{"type": "bar_chart", "props": {
  "title": "見出しの煽り度と、再生の伸び",
  "bars": [
    {"label": "ふつうの見出し", "value": 100},
    {"label": "「日本、終わる」", "value": 195}
  ],
  "accentIndex": 1,
  "conceptual": true
}}
```

### `line_compare` — 折れ線の比較(最大3本)
推移・「AがBを追い抜く」に。線は手描き風のラフエッジで伸びていく。
```json
{"type": "line_compare", "props": {
  "title": "ウソと本当の広がり方(概念図)",
  "series": [
    {"label": "本当", "values": [10, 16, 22, 27, 31, 34, 36], "color": "ink"},
    {"label": "ウソ", "values": [10, 20, 34, 52, 72, 88, 100], "color": "red"}
  ],
  "conceptual": true
}}
```

### 一点物: `C13AttentionFlow`
視線→再生→広告費の分解図ボード。JSONではなく専用作り込み。
Studioの左リストから選ぶ / `npm run render:c13` で書き出し。

### どの型を使うか迷ったら

| 伝えたいこと | 型 |
|---|---|
| AよりBが多い・大きい | bar_chart |
| 時間とともに変わる・追い抜く | line_compare |
| 数字や固有名をドンと1〜4個 | stat_card |
| 人の発言・逸話 | quote |
| 結論の断言 | statement |
| 章の区切り・タイトル | title_card |

それでも迷ったら「**このデータで候補を何案か見せて**」とAIに頼む。静止画数案が数分で出るので、見比べて選ぶのが最速。

## 8. シーンの追加・削除・並べ替え

JSONの `"scenes": [ ... ]` の中の `{ }` ブロックが1シーンです。

- **追加**: 既存ブロックをコピーして下に貼り、中身を書き換える(ブロック間のカンマを忘れずに)
- **削除**: ブロックごと消す
- **並べ替え**: ブロックの順番を入れ替える(動画は上から順に再生される)
- 尺は全シーンの合計から**自動計算**されるので何も気にしなくていい

## 9. 写真・画像を入れる

1. 画像を `public/photos/ep01/` に入れる(フォルダはエピソードごと。名前は半角英数、例: `hearst_portrait.jpg`)
2. quoteのJSONに2行足す:
```json
"image": "photos/ep01/hearst_portrait.jpg",
"imageCaption": "W・R・ハースト(1900年代)"
```
写真は自動で白フレーム+セピア調になり、紙面に馴染みます。

**権利ルール(v4.1・3段階)**: ①一般人の顔は使わない ②存命の公人は権利クリアな写真(公式広報・CC・購入)＋解説目的ならOK(侮辱的な使い方・サムネ釣りは禁止) ③歴史人物(故人)はパブリックドメインならOK——Wikimedia CommonsのPD画像がおすすめ。加害者(ゲッベルス等)も可だが、抑制的に資料として。

## 10. 新しい画が欲しいとき(こだわりカットの頼み方)

AIに次を伝える(**あるものだけでいい**):

1. どのカットか(コンテNo、なければ言葉で)
2. **何を感じさせたいか**(「不気味さ」「数字の暴力性」「静けさ」——これが一番効く)
3. 参考(手描きスケッチの写真、他動画のスクショ、URL)
4. 使いたい素材(写真など)

**流れ**: まず静止画(スタイルフレーム)が1〜3案出る → 画面を見てダメ出し → OKが出たら動きがつく → 完成。
また使いたくなったら「型」に昇格してJSONから呼べるようになる。

## 11. 困ったとき

| 症状 | 原因と直し方 |
|---|---|
| 文字が「せ」など変になる | Chromeの翻訳機能。翻訳アイコン→「元に戻す」。動画の書き出しには影響なし |
| 「未知のシーンtype」エラー | `"type"` の綴りが7章のカタログと違う。コピペし直す |
| 赤いエラー画面(zod) | propsの書き方がおかしい。カンマ・クォート・数値/文字の別を確認 |
| 画像が出ない | 画像が `public/` の下にあるか、パスの綴りを確認 |
| プレビューが更新されない | ブラウザをリロード。それでもダメならターミナルで Ctrl+C → `npm run dev` |
| 書き出しが遅い | 正常です(60秒動画で3〜5分)。急ぎなら該当シーンだけのJSONを作って書き出す |

## 12. ファイル地図

```
remotion_mg/
├─ data/                  ← ★あなたが編集する場所(シーンJSON)
├─ public/photos/         ← ★写真の置き場所
├─ out/                   ← 書き出された動画・静止画
├─ src/kit/
│   ├─ theme.ts           ← 番組の色・フォント(変えるときはAIに相談)
│   ├─ stages.tsx         ← 紙・墨の背景と質感
│   ├─ registry.tsx       ← 型のカタログ本体
│   └─ components/        ← 各型の実装
├─ 使い方マニュアル.md     ← このファイル
└─ README.md              ← 開発者向けの要約
```

**原則: `data/` と `public/photos/` 以外は編集しない。** デザインや動きを変えたいときはAIに「こう変えたい」と伝える。
