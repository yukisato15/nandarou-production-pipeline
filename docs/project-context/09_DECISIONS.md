# Decisions / ADR

## ADR-001: RemotionとPremiereを併用する

- **決定**: Remotionは再現可能な情報画・テロップ・専用MG、Premiereは実写・音・最終編集を担当。
- **理由**: コードの再生成性と、編集者のタイミング/呼吸の判断を両立するため。
- **影響**: Remotionの尺を最終TCとみなさない。Premiere側の配置を前提にする。

## ADR-002: JSON→registry→Zodで制作する

- **決定**: 制作ループではJSONだけを書き、`registry.tsx`に登録済みの型から選ぶ。
- **理由**: AIの自由なコード生成による品質・保守性のばらつきを防ぐため。
- **影響**: 新しい画の型は拡張ループ（静止画承認）を通る。

## ADR-003: 色・フォント・質感を集約する

- **決定**: `theme.ts`と`stages.tsx`を共通基盤とする。
- **理由**: 各コンポーネントが勝手に新ルックを発明するのを防ぎ、番組の一貫性を守るため。
- **影響**: 固有演出の例外は専用Compositionに閉じ込め、標準型へ逆流させない。

## ADR-004: S1/S2〜S6を役割分担する

- **決定**: S1はPremiere SRT、S2/S3/S5はTelopOverlay、S4はstatement/JsonScenes、S6は画像側。
- **理由**: 標準字幕と演出テロップを同じ素材として扱うと、重複・同期・可読性の管理が崩れるため。

## ADR-005: テロップはカット単位で納品する

- **決定**: `render_telops_per_cut.sh`で各カットを0秒始まりの透過ProResにする。パート単位の絶対時間出力は旧仕様。
- **理由**: コンテのTC目安は確定TCではなく、実編集で尺が変わるため。
- **影響**: `package.json`に旧`render:telops:p*`が残るが、納品手順では使わない。

## ADR-006: 可読尺をコンテ尺より優先する

- **決定**: `conte2telops.py`の`required_frames()`で5.5字/秒を基準に表示尺を確保する。不足はconflictとして報告する。
- **理由**: 固定24Fでは長文が読める前に消える事故があったため。
- **影響**: 必要ならコンテTCを人間が延長する。黙って詰めない。

## ADR-007: 権利・資料・AIの境界を明示する

- **決定**: `public/`内の素材を明示管理し、実在ブランド/人物の模倣を避け、出典と概念図注記を常設する。
- **理由**: 番組の誠実性と法務リスクを守るため。

## ADR-008: アイキャッチは専用Compositionとして隔離する

- **決定**: `NandarouKaitaiIdent`と`ident/timing.ts`で音声・HUD・グリッチ・最終ロゴを管理する。
- **理由**: 標準データMGのルールをアイキャッチ固有の演出へ混ぜないため。
- **現状**: v7時点で最終ロゴbbox検査（18/18/28px）が実装され、音声は5.5055秒/30fps。変更時は専用検証を行う。
