# C13 カメラリグ修正仕様(ズームアウト不自然問題)

対象:`build_c13_master.py` / `generate_c13_master.jsx` のカメラ実装 症状:右寄りから全景へのズームアウトで、位置移動とスケール変更が合成され不自然な軌道になる。

---

## 1\. 原因

1. **PositionとScaleの二重補間。** ボードを平行移動(Position)させながら縮小(Scale)すると、画面上の注視点の軌跡は2つの独立した補間の合成になる。中間フレームでは「まだ寄っているのに中心はもう全景側へ移動中」という状態が生じ、被写体が斜めに滑る弧を描く。  
2. **空間補間のオートベジェ。** AEは位置系キーの空間補間がデフォルトでオートベジェのため、直線移動のつもりでも勝手に膨らんだカーブになる。  
3. (該当すれば)微動wiggleがキーフレームと同じレイヤーに同居していると、補間との干渉でさらに濁る。

## 2\. 設計:アンカーポイント・カメラ(Position凍結)

2Dボード撮影の正攻法。**「どこを見るか」と「どれだけ寄るか」を、同一レイヤーの2プロパティに正規化する。**

CAM\_DRIFT(ヌル)← wiggleはここだけ。キーは打たない

 └ BOARD(3840×2160プリコンポ)

     Position     \= \[960, 540\] 恒久固定。キー禁止

     Anchor Point \= 注視点(ボード座標)← カメラの首振り

     Scale        \= ズーム(全景=50%、寄り=85%)← カメラの寄り引き

- Positionを固定しAnchor Pointを動かすと、「レイヤーを動かす」のではなく「見る場所を変える」挙動になる。Scaleは常にAnchor(=注視点)を中心に掛かるため、**ズーム中も被写体が画面中央に張り付いたまま**になり、合成軌道の問題が構造的に消える  
- AnchorとScaleのキーは**必ず同時刻・同イージング**で打つ  
- Anchorの空間補間は**リニア固定**(オートベジェ禁止)  
- wiggleは親ヌルCAM\_DRIFTのみ。`wiggle(0.3, 3)` 程度

## 3\. キーフレーム表(ボード座標=仕様書座標×2、23.976fps)

## 4\. ドロップインJSX(Codex用)

// keys: \[{f:フレーム, look:\[x,y\](ボード座標), zoom:数値}\] zoom 1.0=全景

// baseScale: BOARDが2倍解像度なら 50

function applyCameraRig(boardLayer, keys, fps, baseScale) {

    var tr  \= boardLayer.property("ADBE Transform Group");

    var ap  \= tr.property("ADBE Anchor Point");

    var sc  \= tr.property("ADBE Scale");

    var pos \= tr.property("ADBE Position");

    while (ap.numKeys)  ap.removeKey(1);

    while (sc.numKeys)  sc.removeKey(1);

    while (pos.numKeys) pos.removeKey(1);

    pos.setValue(\[960, 540\]);                    // 恒久固定

    var i, tk, s;

    for (i \= 0; i \< keys.length; i++) {

        tk \= keys\[i\].f / fps;

        ap.setValueAtTime(tk, keys\[i\].look);

        s  \= baseScale \* keys\[i\].zoom;

        sc.setValueAtTime(tk, \[s, s\]);

    }

    var eIn  \= new KeyframeEase(0, 33);

    var eOut \= new KeyframeEase(0, 60);

    for (i \= 1; i \<= ap.numKeys; i++) {

        ap.setTemporalEaseAtKey(i, \[eIn\], \[eOut\]);

        ap.setSpatialTangentsAtKey(i, \[0, 0\], \[0, 0\]);   // 弧の根絶

        sc.setTemporalEaseAtKey(i, \[eIn, eIn\], \[eOut, eOut\]);

    }

}

適用:既存のPosition/Scaleアニメコードを全削除し、§3の表を配列で渡すだけ。最終引きキーのeaseだけ個別に(70/25)上書き。

## 5\. それでも気持ち悪ければ:演出の代替案

ズームアウトという運動自体をやめる選択肢もある。**¥紙片のホールド明け、スタンプSEと同時に全景へハードカット**(204Fでカット→全景静止1.1s→FLASH)。ドキュメンタリー編集の文法としてはむしろ強く、番組の「抑制」の美学とも合う。判断基準:アンカーリグ版を一度レンダーして、引きが「カメラマンの仕事」に見えなければカットを採用。承認スタイルフレーム(全景の決め画)はどちらでも保たれる。
